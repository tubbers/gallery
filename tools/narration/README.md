# Gallery narration: build and rollout

**Daily workflow:** Astra prepares four short blocks from the gallery entry and its capture notes, verifies the astronomy and writes a draft. Approve the words, render on the computer that already has the Google voice key, then test and publish the four MP3s together. Legacy audio stays in place. No new server, Google Cloud project, GitHub secret, or paid subscription is needed for the helper itself.

1. **Pilot:** M74 already has five working files on the Gallery. Use it as the live reference, not as an object to regenerate or overwrite. The earlier four original Windows files and catalogue source were named in the handoff but are not needed to test the existing player. M33 is the next new four-part entry. Check its chart, portrait, Moon scale and scope photo.
2. **Draft:** Use the exact Gallery image label and a unique lowercase image ID. Write short spoken Australian English. Introduce the object, constellation and one rounded distance; give the discoverer and context; begin the science with the Moon comparison, then tell people what they can see and why it matters; end with the telescope, site and month/year (never the day). Save the factual sources outside the spoken text. Set status to approved only after editorial review.
3. **Voice check and render:** Existing Google Cloud Text-to-Speech project and Callirrhoe (en-AU), MP3, rate 0.9. Run one intro first to check voice, pace and pronunciation before approving the full set. No automatic network retries, 6,000 characters maximum per invocation, and unchanged completed clips are reused. No calls on plan. See [Google pricing](https://cloud.google.com/text-to-speech/pricing); the project still needs billing enabled, and charges only apply past its free usage limit as described there. Do not enable billing or change permissions for the pilot.
4. **Stage:** Keep the output folder intact. Decode and listen to the clips; verify the hashes against `gallery-record.json`. Check every overlay resolves to an existing, credited asset. Stage the four MP3s under `audio/` and add `narration` to the exact label in the latest `assets.json` in the same commit. No change to the Gallery player is needed. Never upload the key, debug files, draft or render manifest. If a live entry later needs new audio, use a new image ID so browsers don't reuse old cached clips.
5. **Verify and expand:** On a phone and desktop, tap the speaker, check the four clips in order, the Moon then disappears after roughly four seconds, other overlays clear at the end, and stop/next photo clears playback. Check existing five-part M74 still works. If a file is bad, revert that one audio/metadata commit. Start with one then small batches of reviewed new entries, not a rerender of the live catalogue. SkyDome should link to the Gallery listening experience if desired rather than acquire a second player or duplicate the audio in the first rollout.

## Operator reference

On Windows with standard Python 3.10+ and Tk installed, the saved helper may be double-clicked to choose a narration JSON, then choose either a one-clip test or a four-clip render. For a short draft it displays all four parts and asks for approval before rendering. It opens the local output folder, without publishing anything. It reads the existing `GOOGLE_TTS_KEY` environment setting (or its persisted Windows user setting). Keep the key on the PC; never paste it into chat, a command or GitHub. A key that was only set in an older terminal may require running from the existing local voice setup.

For terminal or automated runs: `python gallery_narration.py plan script.json`, `python gallery_narration.py sample script.json`, or `python gallery_narration.py render script.json`. Optional `--out` chooses the local output parent. Files go under the image ID. If a source changes after a clip has been rendered, choose a new output folder to preserve the previous result. If an interrupted run left a lock, check it is not running before using a new folder.

Script format: object with `schema: 1`, `status: "draft" | "approved"`, `label`, `image_id`, `captured: "YYYY-MM"`, and `spoken_script: {"intro": "...", "discoverer": "...", "science": "...", "scope": "..."}`. The historical `gallery_narration_v1.2.0.json` was not available for this build. Inventory it and review its actual format before importing it; never auto-split unlabelled prose or overwrite current recordings from it.

For staging, run `python stage_gallery_narration.py approved-script.json rendered-image-folder latest-gallery-checkout new-patch-folder` on the computer preparing the commit (with FFmpeg available). It checks exact catalogue label/month, overlay files, fingerprints, existing paths and full MP3 decoding. The resulting patch contains only the four MP3s and updated `assets.json`; it does not modify the checkout or push anywhere.
